# QCM-Log: pass-level event logs of quantum circuit compilation

QCM-Log records what five quantum compilers actually execute. Each **compilation is a
case** and each **pass execution is an event**, with its order, nesting, duration, IR
change and outcome. The logs come as a flat CSV, pass- and stage-level XES, and OCEL 2.0.

This README documents the dataset and maps every claim in the short paper
(`parts/main.tex`, ICSE 2027 Tool Demonstration and Data Showcase track) to the file or
script that supports it. All numbers below are generated by
`paper/scripts/make_tables.py` (written to `paper/generated/stats.tex`) unless a
different source is named.

- Dataset (Zenodo): `https://zenodo.org/records/23614607`

## Repository layout

```

  pm_qiskit_example.py    the process-mining example of the paper (Section V)
```

Raw CSVs under `results/` are stored in Git LFS (`git lfs pull` if they are 3-line

There are 52 run folders: one per non-default configuration, and for the defaults
the v1 run (four toolchains, CORE circuits), one EXTENDED run per toolchain and one
Kirin run on all circuits. The v1 run's Kirin events predate fixed-point tracing and
are superseded by `results/v2/kirin-fixpoint`.

## Schema (summary)

Table II of the paper lists every attribute; the long paper's Table "Schema" gives the
full definitions.

- **Identity and order:** `case_id` (`<tc>__<circuit>__r<rep>`, prefixed `<run>/` when
  merged), `run_token` (per-job join key), `toolchain`, `event_index` (0-based
  pre-order, parents first; the authoritative order), `seq`, `iteration`
- **Activity:** `activity` (pass class or transformer; `Fixpoint[<rules>]` for Kirin
  rewrite iterations; outcome name), `activity_module`, `pass_kind`, `phase`
  (`load`, `compile`, `outcome`), `stage`
- **Nesting:** `nesting_depth`, `parent_activity` (Qiskit: native stage, e.g.
  `stage:layout`), `is_container`
- **Measures:** `start_unix_ns`, `duration_ns` (tracing overhead subtracted),
  `ir_changed` with `changed_method`, `size_before`, `size_after`, `mem_peak_bytes`
  (memory repetitions only; not recorded for BQSKit)
- **Case:** `circuit_id`, `algorithm`, `num_qubits`, `selection_tier`,
  `portability_tier`, `input_format`, `input_sha16`, `barriers_stripped`, `run`,
  `opt_level`, `seed`, `topology`, `device_qubits`, `rep`, `mem_traced`, `versions`,
  `status`, `error`, `load_ms`, `compile_ms` (whole call, tracer overhead included),
  `n_events`, `out_ops`, `out_2q_ops`, `finished_utc`

`status` is `ok`, `load_error` (input rejected), `compile_error`, `timeout` (600 s) or
`crash` (worker died, e.g., killed for memory).

### Conventions you need for correct analyses

1. **Order by `event_index`, not by timestamp.** Start times never decrease along it,
   but XES and OCEL timestamps have microsecond resolution.
2. **Compare toolchain-specific attributes within one toolchain only:**
   `pass_kind`, `ir_changed` (DAG/tape/circuit fingerprint, circuit equality, or Kirin's
   rewrite result), sizes (Kirin counts IR statements), `mem_peak_bytes`.
3. **Do not double-count time.** Containers enclose their children, and Kirin's
   `rewrite_iteration` events are nested inside their pass. Sum leaf events only.
4. **Each case ends with one outcome event** (`compilation ok`, `load error`,
   `compile error`, `timeout`, `crash`), 1 µs after its last pass or at completion if no
   pass ran. Most failures have no pass events; only Kirin's compile errors leave
   partial traces (96 compilations, 126,123 events).
5. **Filter the pass log by `toolchain` and configuration** (`run`, `opt_level`,
   `topology`, `seed`). Pass vocabularies are disjoint across toolchains; the stage log
   is the cross-toolchain view.
6. **Keep nanosecond timestamps out of float64 columns.** Pandas NaN promotion rounds
   them by about 100 ns.

## Quick start

```python
import pandas as pd
log = pd.read_csv("results/merged_v2/event_log.csv", low_memory=False,
                  dtype={"opt_level": str, "seed": str})
# Qiskit, default configuration, first repetition, successful compilations
q = log[(log.toolchain == "qiskit") & (log.opt_level == "2") & (log.topology == "grid")
        & (log.seed == "42") & (log.rep == 0) & (log.status == "ok")
        & (log.phase != "outcome")].sort_values(["case_id", "event_index"])
variants = q.groupby("case_id").activity.agg(tuple).nunique()   # 8
```

```python
import pm4py
ocel = pm4py.read_ocel2_sqlite("results/merged_v2/event_log.ocel.sqlite")
```

The XES files are large. For a single toolchain or configuration, filtering the CSV
(as `experiments/pm_qiskit_example.py` does) is faster than loading the full XES.

## Reproducing the data and the paper

```bash
./setup_envs.sh                                  # 5 toolchain venvs + merge venv (Python 3.11-3.13)
python3 run_all.py --corpus qcm-corpus-v1        # v1 baseline -> results/
caffeinate -i ./experiments/v2_factorial.sh      # v2 run folders -> results/v2/
.venv/bin/python merge_logs.py --include-failed --outcome-events --ocel --out results/merged_v2 \
  --results v1=results:qiskit,cirq,pennylane,bqskit $(ls -d results/v2/*/)
.venv/bin/python paper/scripts/make_tables.py    # every number and table -> paper/generated/
.venv/bin/python experiments/pm_qiskit_example.py
```

Runs are resumable, since finished `case_id`s are skipped. A `case_id` does not encode
the settings, so every setting needs its own `--out` folder. Timings depend on the
machine; pass sequences, outcomes and input hashes do not, except for BQSKit, whose
traces vary for 15 of 144 CORE circuits even under a fixed seed.

## Limitations

- **Corpus:** one benchmark suite whose OpenQASM was written by Qiskit, which may favour
  Qiskit's importer. Only Qiskit reads the 29 OpenQASM 3 circuits.
- **Measurement scope:** timings come from one machine. Non-default configurations
  were compiled once, and BQSKit's cover the CORE circuits one factor at a time.
- **No quality ranking:** native bases differ and Kirin/Bloqade does not route, so the
  logs do not rank output quality across toolchains.
- **Toolchain-specific semantics:** IR change, size and memory are defined per
  toolchain. Barriers were removed from all inputs, and the Qiskit seed also changes
  the synthetic calibration data.
- **Stage mapping:** all 86 mappings are marked `suggested` in `pass_stage_map.csv`
  and await independent validation.
